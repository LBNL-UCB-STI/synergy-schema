# Costs and exit

The first mapping is the most work, because interfaces, ownership, and known
losses all have to be spelled out. Measure how long it takes to prepare, use,
and inspect that first real exchange before setting targets for repeat
exchanges or for changing a mapping.

Adoption can be undone. Existing payloads, readable review tables, and plain
manifests stay useful even if the Synergy checks are later dropped. Nothing
depends on a proprietary runtime or a hidden registry.

Flat files plus a README can be enough for a stable, one-off exchange. Stable
IDs, structured mapping rules, and review records start paying off when
deliveries repeat, scenarios change, or debugging spans several teams.
